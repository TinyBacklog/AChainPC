# M3 Jogável a 30fps — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** O jogo é configurado por um `astralchain.ini` próprio (controlos, janela, áudio),
guarda os saves em `$XDG_DATA_HOME/astralchain/` e passa a checklist manual com 0
fallbacks.

**Architecture:**
- O frontend continua a ler o `sdl2-config.ini` do perfil, que é a config completa do
  suyu. Por cima dele aplica um ficheiro pequeno, o `astralchain.ini` (flag nova
  `--ini=PATH`), que só tem as chaves que interessam ao jogador.
- Os controlos usam presets embutidos (`steam_controller`, `keyboard`) ou `custom`,
  com strings de parâmetros do suyu.
- É o `acre.py run` que cria o ini, a partir de um template versionado. Escolhe o preset
  pelo hardware USB presente.
- O perfil de jogo passa de `work/profile` para `$XDG_DATA_HOME/astralchain/profile`.
  A migração é automática.

**Tech Stack:** C++20 (frontend, simpleini), Python 3 stdlib, SDL3.

**Spec:** `docs/superpowers/specs/2026-10-14-astralchainre-design.md` (secções 8 e 10).

## Global Constraints

- O `astralchain.ini` é procurado ao lado do binário e depois em
  `$XDG_CONFIG_HOME/astralchain/`. Se não existir, é criado com os defaults comentados.
- A NAND e os saves vivem em `$XDG_DATA_HOME/astralchain/`.
- A janela abre no monitor primário por defeito (`display_index = 0`).
- O GUID do Steam Controller Puck (28de:1304) depois de o runtime limpar o CRC é
  `03000000de2800000413000002006800`.
- Os M4 (`fps60`, `resolution_scale`) ainda não existem. As chaves só entram no ini no M4.
- Commits como `kadinho`, sem push.

## Review Focus

1. **Migração do perfil com saves para outro filesystem** (`/var/www` → `/home`).
   Esperado: os saves são copiados e só depois apagados da origem. Nunca se perdem se a
   cópia falhar a meio (Task 3).
2. **Ini com erros** (chave desconhecida, valor inválido). Esperado: aviso no log com a
   chave, o valor default é usado, e o jogo arranca (Task 1).
3. **`display_index` fora do intervalo** (por exemplo, um monitor desligado). Esperado:
   cai para o primário com aviso (Task 2).
4. **Preset `steam_controller` sem o comando ligado.** Esperado: o jogo arranca e o
   teclado não fica mapeado. Isto fica documentado no ini (Task 1).
5. **`run` depois de um `export` novo sem `build`.** Esperado: erro "build is older than
   export; run `acre.py build`" (Task 4).

**Interfaces:**
- `struct AcreIni { bool fullscreen; bool vsync; int display_index; int volume; std::string preset; std::map<std::string, std::string> custom; std::vector<std::string> warnings; };`
- `AcreIni ParseAcreIni(const std::string& text);` é puro e testável.
- `void ApplyAcreIni(const AcreIni&);` escreve em `Settings::values` (`fullscreen_mode`
  não muda; `vsync_mode` ↔ `vsync`; `volume`; `players[0]` conforme o preset).
- `std::span<const std::pair<std::string_view, std::string_view>> SteamControllerPreset();`
  devolve as 19 bindings.

Formato do template:

```ini
; AstralChainRe settings. Delete this file to get the defaults back.
[display]
; Start in fullscreen (borderless). F11 toggles in game.
fullscreen = false
; 0 = primary monitor; 1, 2, ... other monitors in SDL order.
display_index = 0
vsync = true

[audio]
; 0-100
volume = 100

[controls]
; steam_controller, keyboard or custom.
; steam_controller expects a Steam Controller (Puck 28de:1304) through SDL HIDAPI;
; without it connected nothing is mapped, so pick keyboard instead.
preset = keyboard
; With preset = custom, one line per input using suyu parameter strings, e.g.
; button_a = engine:sdl,port:0,guid:...,button:1
```

### Task 2: `display_index` e janela

**Files:**
- Modify: `frontend/emu_window/emu_window_sdl2_vk.cpp`, `emu_window_sdl2.cpp`/`.h`
  (posição inicial e fullscreen no display escolhido)

- [ ] **Step 1: Implementar.** Depois de `SDL_CreateWindow`:

```cpp
int count = 0;
SDL_DisplayID* displays = SDL_GetDisplays(&count);
const int index = AcreDisplayIndex();
if (displays && index >= 0 && index < count) {
    SDL_SetWindowPosition(render_window, SDL_WINDOWPOS_CENTERED_DISPLAY(displays[index]),
                          SDL_WINDOWPOS_CENTERED_DISPLAY(displays[index]));
} else if (index != 0) {
    LOG_WARNING(Frontend, "display_index {} out of range ({} displays); using primary", index, count);
}
SDL_free(displays);
```

  `AcreDisplayIndex()` vem do `AcreIni` aplicado, guardado num global do frontend. Com
  o índice 0, a janela fica no `SDL_GetPrimaryDisplay()`, que tem de ser o primeiro da
  lista. Se não for, usa-se `SDL_GetPrimaryDisplay()` diretamente.
- [ ] **Step 2: Verificar com o utilizador** (manual): `display_index = 0` abre no
  primário, e um índice fora do intervalo gera warning e abre no primário.

### Task 3: Perfil em `$XDG_DATA_HOME/astralchain`, ini criado pelo `acre.py`

**Files:**
- Modify: `tools/acre/config.py` (`play_profile()`, `ini_path()`)
- Create: `tools/acre/profile.py` (`migrate(old, new)`, `ensure_ini(path)`, `detect_preset()`)
- Modify: `tools/acre/setup.py`, `tools/acre/run.py`
- Create: `tools/acre/tests/test_profile.py`

**Interfaces:**
- `config.play_profile() -> Path` = `$XDG_DATA_HOME/astralchain/profile`.
- `config.ini_path() -> Path` = `$XDG_CONFIG_HOME/astralchain/astralchain.ini`.
- `profile.migrate(old: Path, new: Path) -> bool`:
  - Se `new` não existir e `old` existir: copia `old` para `new.tmp` (copytree), muda
    o nome para `new` e só então apaga `old`.
  - Se `new` existir, não toca em nada.
  - Devolve se migrou.
- `profile.detect_preset(usb_root=Path("/sys/bus/usb/devices")) -> str` devolve
  `steam_controller` se algum `idVendor`/`idProduct` for `28de`/`1304`, e `keyboard`
  noutros casos.
- `profile.ensure_ini(path, template, preset) -> bool` copia o template com
  `preset = <preset>` se o ficheiro não existir. Nunca o sobrescreve.
- `run` passa `--ini=<ini_path>` e `--user-dir=<play_profile>`. Os scripts antigos
  usavam o `game.json["profile"]`: isso é migrado e atualizado.

  - `migrate` não faz nada se o destino existir;
  - uma falha de cópia (destino read-only) mantém a origem intacta;
  - `detect_preset` com um `/sys` falso;
  - `ensure_ini` não sobrescreve um ficheiro existente.
- [ ] **Step 2: Implementar (GREEN).**
